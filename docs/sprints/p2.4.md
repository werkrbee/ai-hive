# P2.4 — AI observability

Goal: a person can see which agents run, who owns them, how they behave, what risks need
attention, what they cost and whether accepted outcomes improve, from evidence that says
how fresh and how complete it is. Rationale and the boundary: `docs/observability.md`.

Every item is an issue under epic #369, in four sprints, each with a tracker issue.
Work them in the order below with `/work <issue>`. The order is a sequence, not a
calendar or a capacity commitment. The maintainer owns each decision, and each PR needs
green CI and an independent Patricia review.

**Guardrail:** observing never moves a source of truth or a gate. Projections are
rebuilt from their owners' records and name them; losing or sampling telemetry never
weakens an audit entry, a budget check or an approval; and an alert or a proposal never
acts on its own. Nothing here is hosted, live or billable: acceptance and CI use
synthetic records.

## Definition of done

- An ownerless agent can be found.
- A slow run can be followed to the step that was slow.
- Quality drift can be weighed against the version and change behind it.
- A risk can be handed to the person accountable, with its evidence.
- Cost and accepted outcomes can be read together, with unattributed spend shown.
- With observability off, every agent works as before, with no new dependency.
