# P2.2 — the learning loop

Goal: an agent learns from its own history, and keeps what it learned when its model
changes. A person delegates a goal, steers the run when it comes back for direction, sees
it while it runs, and knows what each accepted outcome cost. Rationale:
`docs/frontier-ecosystem.md`.

Every item is an issue on the `P2.2 — learning loop` milestone (epic #140). Work them in
the order below with `/work <issue>`, after hosted Barry is deployed (#120).

**Guardrail:** what an agent learns enters through a reviewed change, never on its own.
A proposed eval case or lesson changes the agent's pins, so it needs a new baseline like
any other change, and direction given to a run can narrow what it does but never widen
it.

Close the epic (#140) when all seven are done.

## Definition of done

- A product can see, for each agent, what an accepted outcome cost.
- Every agent appears in one inventory with its owner, version, spend and eval status.
- A run can be followed while it runs, in any OpenTelemetry backend.
- A person can steer a paused run without widening what the policy allows.
- A human decision on a review item can become an eval case and a lesson, through review.
- Changing an agent's model keeps its lessons and must pass its eval with them.
