# P2.3 — harness alignment

Goal: the House works, verifiably, in the twenty harnesses where people build agents: ten
pro-code harnesses that install its artifacts, and ten low-code harnesses that call its
agents and tools over MCP and A2A. Each one has a dated capability row with its billing
unit and retail price, a conformance check or a recorded call, and a guide. Rationale,
the ranking and the cost unit: `docs/harness-ecosystem.md`.

Every item is an issue on the `P2.3 — harness alignment` milestone (epic #229). Work them
in the order below with `/work <issue>`. It can run alongside the learning loop (P2.2):
the two touch different files, and the cost columns here feed cost per accepted outcome
(#142).

**Guardrail:** aligning a harness never forks a portable artifact. A skill, rule or agent
stays one file; an adapter folder gets content only where a harness's behavior has to
diverge. Every path, capability and price the House records names the vendor document and
the date that say so, and a price nobody has published is recorded as not published,
never estimated.

## Definition of done

- One registry is the only place a harness, an install path or a price is written down.
- Each of the twenty has a row with its billing unit, retail price, source and a date no
  older than 90 days, and an effective rate per million tokens wherever one is published.
- CI installs the House for each pro-code harness and finds every file where its row says.
- Barry and Patricia have been run in each pro-code harness, and each low-code harness
  has called hosted Patricia, with the date and units recorded.
- Each of the twenty has a guide, and one index links them.
- The twenty are re-checked every quarter and change only through a reviewed edit.
